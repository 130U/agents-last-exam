# UniPat 两道 benchmark 作业：准确拆解

## 最短答案

1. **主作业（偏交付）**：先讲清楚你对 Agents' Last Exam 的理解，再说明如果由你负责，怎样把 ALE 这种 task 做成一个 1,000 道、可规模化生产且可验收的项目。
2. **附加题（偏研究）**：自选一个专业领域或能力方向，研究其中最重要的现有 benchmark，找出真实测量缺口，再提出一个具有创新点的新 benchmark 构想。

第一题考“已有方向能不能被你交付出来”；第二题考“未知方向能不能被你研究出来”。

## 任务一：ALE 类 1,000-task 项目方案

### 面试官明确要求

- 研究并理解 ALE。
- 说明你怎样理解这个 benchmark。
- 说明这种 task 应怎样构造。
- 假设你领导一个项目构建 1,000 道同类 task，你准备怎样做。
- 这是最主要的、偏交付型的小作业。

### 最稳妥的交付内容

1. **ALE 定义与边界**：它测试的是 agent 完成长程、真实数字化专业 workflow 并交付可验证产物，不是普通问答，也不是单纯测基础模型知识。
2. **先定义“1,000 道”的计数单位**：是 1,000 个互不相同的 workflow，还是同一 workflow 下带不同输入的 1,000 个 runnable instances？两者的专家和工程成本完全不同，作业中应先写清假设。
3. **单条 task anatomy**：Task Description、Input、Software/Environment、Output、隐藏 reference、Evaluation；并解释 complex、representative、verifiable。
4. **1,000 题覆盖设计**：领域 / 能力 taxonomy、workflow family、各类配额、难度梯度、公开/私有或 train/dev/test 划分。
5. **人员与职责**：你定义专家画像、标准、校准和验收；专家运营团队负责招募，领域专家负责生产与审核，工程/QA 负责环境和 evaluator。
6. **生产流水线**：客户需求澄清 → task spec → 小规模 gold pilot → 专家 calibration → 双层 review → 工程 dry-run → agent pilot → bad case 修复 → 分批放量 → 最终验收。
7. **质量控制**：歧义、多个合理答案、shortcut、数据泄漏、grader 稳定性、任务不可复现、环境失败、难度失衡。
8. **交付指标**：覆盖度、一次通过率、返工率、专家一致性、evaluator 稳定性、有效难题率、环境成功率、成本和进度。具体目标值必须标为假设。
9. **一题完整样例**：不是转写中的硬要求，但强烈建议附上，用它展示上述 schema、rubric 与 QA 如何真正落地。

### 你不需要做什么

- 不需要真的写 1,000 道题。
- 不需要只做 ALE 文献综述或 leaderboard 对比。
- 不需要自己从零建立全部专家池；面试前文已经说明公司有专家运营团队和供应商。
- 不要编造客户预算、交付周期或 SLA；转写没有提供。

## 任务二：原创 benchmark 构想

### 面试官明确要求

- 自选方向；可以按专业领域划分，也可以按能力或任务形态划分。
- 先研究该方向中高质量、热门、真正相关的 benchmark。
- 找出现有 benchmark 没覆盖好或没衡量准的地方。
- 由这个 gap 推导出一个有创新点的新 benchmark 构想。
- 这是附加题，不要求短期内做成完整 benchmark。

### 最稳妥的交付内容

1. **Target construct**：一句话说清楚你到底想测哪种能力，而不是只说“法律 / 数学 / 多模态”。
2. **Related benchmark map**：选少量最相关的强 benchmark，比较对象、任务形态、数据来源、环境、评分方式与主要盲区。
3. **Gap evidence**：指出已有 benchmark 为什么测不到、测不准或容易被 shortcut 绕过某个重要能力。
4. **创新假设**：新设计增加的不是“更偏门 / 更难”，而是一个此前没有被有效隔离和测量的能力。
5. **Benchmark design**：任务单元、数据来源、环境、评价指标、anti-gaming、污染控制和版本策略。
6. **少量任务原型**：给 1–3 个例子证明这个构念能转化为数据；属于增强项。
7. **验证与否证**：什么 pilot 结果会支持这个 benchmark 有效，什么结果会说明想法不成立。
8. **研究与商业价值**：它能告诉模型厂商什么，未来是否可能转成 OTS 数据集或客户项目。

### 你不需要做什么

- 不需要完成完整论文、代码仓库、数据集或大规模评测。
- 不需要扫描“数十万、上百万”个 benchmark；围绕一个窄问题识别真正相关的 frontier work 即可。
- 不限于数学或法律，也不必是行业垂直题。
- 不建议把第二题简单理解为“优化 ALE”；它可以是完全不同的能力 benchmark。

## 优先级与时间分配

如果时间有限，优先把第一题做好。一个合理但非面试官规定的策略是，把约 75%–85% 的时间放在第一题，把第二题做成一份短而尖锐的 concept memo。

## 交付前还需向面试官确认

- deadline
- written memo、slides 还是现场 presentation
- 预计展示时长或页数
- 第一题是否希望看到一条可运行的 demo task
- 第二题是否需要模型 baseline / pilot，还是 concept 即可
