# Draft v1 research refresh plan

**Research date:** 2026-08-09  
**Purpose:** verify the narrow claims required by the first deliverable draft without replacing the repository's existing 01–10 research packages.

## Decision questions

1. What exactly is counted in ALE, and which paper, code, and dataset surfaces must remain separate?
2. What makes an ALE-style task a runnable measurement asset rather than a prompt or metadata row?
3. Which controls are necessary for evaluator validity, environment reproducibility, leakage resistance, and statistical reporting?
4. Which production parameters can be supported by public evidence, and which must remain pilot variables?
5. What minimum end-to-end worked task is needed to demonstrate that the proposed operating model is executable?

## Method

- Freeze mutable sources by revision and access date.
- Separate source fact `[F]`, author/institution claim `[C]`, inference `[I]`, recommendation `[R]`, and pilot/client variable `[P]`.
- Triangulate design recommendations across ALE plus independent benchmark, measurement, and governance sources.
- Preserve exact units: workflow, instance, submission, release, run, trial, attempt, retry, and regrade.
- Subject the draft to a project-lead, technical-reviewer, and procurement-reviewer adversarial pass.

## Scope boundary

This refresh does not estimate staffing, rates, cost, schedule, yield, rework, pool ratios, repeat counts, or quality thresholds. Those values require an instrumented batch zero and stratified pilot.
